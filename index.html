How the math works

This app implements Folding Any Orthogonal Maze (Erik Demaine, Martin Demaine, Jason Ku): draw any orthogonal maze — walls on the edges of an n×n grid — and a single flat square of paper folds into that maze, with walls of uniform height h extruded from a flat floor.

Why the paper is 3× the maze

Extruding a zero-thickness wall of height h costs paper that travels up the wall and back down: 2h extra. So each of the n−1 interior grid lines carries a hidden pleat strip of width 2h, and the two boundary lines need only h each (the paper’s edge becomes the wall’s top rim). Total side length:

n + (n−1)·2h + 2·h = (2h+1) n

This app fixes h = 1, so the sheet is exactly 3n × 3n. Where a strip crosses a wall edge it folds into the wall (two 90° creases at the base, one 180° crease at the ridge top); where it doesn’t, it is folded flat and hidden in the floor.

Why six gadgets suffice for every maze

Away from grid vertices, a strip is trivial. All the difficulty concentrates where strips cross: the vertex gadget. Only the pattern of walls on the vertex’s four incident edges matters — 24 = 16 cases, which reduce to six gadgets up to rotation:

The key invariant: every gadget presents the same interface on each of its four sides — a ridge profile where a wall crosses (90° valleys at ±h, a 180° mountain at the apex) and a floor profile where none does (the flattened pleat). Since any two interfaces of the same kind match, any combination of gadgets tiles into a consistent, watertight crease pattern — no global constraint solving, so the algorithm runs in time linear in the maze size. (This app unit-tests exactly that invariant on both sides of every tile border.)

How close to optimal is 2h+1?

Folding can only shrink intrinsic (along-the-paper) distances. If the maze uses all (n+1)2 grid points, it has at least (n+1)2−1 edges, so some row or column carries about n/2 of them; a straight line across the folded model must climb up and down each of those ridges, giving intrinsic length about n(h+1) + 2h. The flat square’s diameter must be at least that, forcing scale factor ≥ (h+1)/√2. So 2h+1 is within a factor of just under 2√2 of optimal — and within √2 whenever some row or column is fully walled.

Reading & folding the crease pattern

Red = mountain fold, blue = valley fold (printed side up); thin/light lines fold 90°, thick/dark lines fold 180°. Fold all the 180° pleats flat first, then open the 90° creases to raise the walls. The folding is watertight (the paper’s boundary maps onto the model’s boundary), and for h = 1 the number of layers at any point is bounded by a constant. Printing this page prints just the crease pattern.
